# Full Module Plan

## M0 — Project Setup & Provenance

**Goal:** establish a reproducible workspace before touching data.

Tasks:
- Freeze species, source cohort, BioProject and label policy.
- Record all source files in `data/dataset_manifest.csv`.
- Set random seed and modeling protocol in `configs/project.yaml`.

Acceptance:
- `python scripts/00_check_workspace.py` passes.

---

## M1 — Data Collection

**Goal:** collect only the files required for the selected 100-isolate panel.

Collect:
1. Isolate metadata.
2. Genome accession(s) / BioSample identifiers.
3. Published AST phenotype table covering the panel.
4. Published AMR genes/alleles/variants generated by AMRFinderPlus and ARIBA.
5. Optional genome FASTA files only if later sequence-level validation is required.

Store:
- metadata -> `data/raw/metadata/`
- AST -> `data/raw/ast/`
- AMR determinants -> `data/raw/amr/`
- FASTA -> `data/raw/genomes/`

Do not proceed until each file is registered in the manifest.

Acceptance:
- Data sources documented.
- 100-isolate cohort can be identified unambiguously.
- AST and AMR tables contain an isolate key that can be joined to metadata.

---

## M2 — Data Audit & Quality Control

**Goal:** establish exactly what was received before modeling.

Checks:
- Number of unique isolates.
- Duplicate isolate IDs.
- Missing accession IDs.
- Antibiotic names and number of unique drugs.
- S/I/R counts per antibiotic.
- Missing AST values.
- Duplicate/conflicting phenotype records.
- AMR determinant count per isolate.
- Join coverage across metadata, AST and AMR tables.

Outputs:
- `data/reports/data_audit.csv`
- `data/reports/ast_class_counts.csv`
- `data/reports/join_coverage.csv`

Acceptance:
- No unresolved duplicate/conflicting keys.
- Missingness and class balance understood.

---

## M3 — AST Phenotype Processing

**Goal:** create clean antibiotic-specific target labels.

Procedure:
- Standardize antibiotic spelling/casing.
- Standardize phenotype values to `R`, `I`, `S`.
- Preserve `I` in interim data.
- For primary binary tables: `R -> 1`, `S -> 0`, exclude `I`.
- Exclude missing/unknown labels.
- Select antibiotics with enough samples in both classes.

Critical rule:
- Never silently map Intermediate to Resistant or Susceptible.

Outputs:
- `data/interim/ast_standardized.csv`
- `data/processed/master/ast_binary.csv`
- `data/reports/ast_class_counts_after_filter.csv`

---

## M4 — AMR Feature Engineering

**Goal:** convert published AMR calls into ML features.

Primary features:
- AMR gene/allele presence or absence.
- Resistance-associated variants where explicitly reported.

Procedure:
- Standardize gene/allele naming.
- Resolve synonymous spellings without merging biologically different alleles.
- Build isolate x determinant matrix.
- Encode: present = 1, absent = 0.
- Remove invariant features for modeling, but keep an audit list.

Optional later extension:
- Re-run AMRFinderPlus/CARD/ARIBA from sequence files and compare calls with publication.

Outputs:
- `data/processed/master/amr_feature_matrix.csv`
- `data/reports/amr_feature_summary.csv`

---

## M5 — ML Dataset Assembly & Validation Splits

**Goal:** create one reproducible dataset per antibiotic.

For each eligible antibiotic:
- Inner join R/S labels with AMR feature matrix by isolate ID.
- Record sample count and class balance.
- Save X/y table.
- Create fixed stratified 5-fold assignments using seed 42.

Important:
- With 100 isolates, prefer stratified cross-validation over a single random split.
- If lineage/sequence type information exists, add a grouped/lineage-aware robustness experiment to detect inflated performance from related isolates.

Outputs:
- `data/processed/per_antibiotic/<antibiotic>.csv`
- `data/processed/splits/<antibiotic>_folds.csv`

---

## M6 — Logistic Regression Baseline

**Goal:** establish an interpretable baseline.

Use:
- Logistic Regression with regularization.
- Class weights only when imbalance warrants it.

Report:
- Accuracy, Precision, Recall, F1, ROC-AUC.
- Cross-validation mean and standard deviation.
- Coefficients with direction of association.

---

## M7 — Random Forest & XGBoost

**Goal:** test nonlinear feature interactions.

Models:
- Random Forest.
- XGBoost.

Rules:
- Hyperparameter tuning must happen within training/CV logic.
- Do not tune on the held-out test set.
- Save model configuration and random seed.

---

## M8 — Evaluation

**Goal:** compare models fairly per antibiotic.

Required metrics:
- Accuracy
- Precision
- Recall
- F1-score
- ROC-AUC
- Confusion matrix

Also report:
- Number of R/S isolates used.
- Class balance.
- Cross-validation variability.

Do not select a model using accuracy alone.

---

## M9 — Explainability & Biological Interpretation

**Goal:** identify which AMR determinants drive predictions.

Methods:
- Logistic coefficients.
- Random Forest feature importance.
- XGBoost gain/importance.
- Optional SHAP after the core pipeline is stable.

Check whether high-ranking features are biologically plausible for the antibiotic being predicted.

---

## M10 — Final Reporting

Deliverables:
- Clean master dataset.
- Antibiotic-specific ML datasets.
- Model comparison table.
- ROC/confusion-matrix figures.
- Ranked determinant table.
- Reproducible commands and configuration.
- Limitations section, especially small sample size and exclusion of Intermediate phenotypes.
